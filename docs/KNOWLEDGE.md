# 原文依据检索

学生入口 `/knowledge`，接口 `POST /v1/knowledge/search`，正文 `{query, type?, opportunity_id?, limit?}`。行动助手在读取机会或资格时附带匹配的 `references`；写操作仍走原来的确认流程。这里只检索证据，不生成资格结论。

## 内容公开流程

1. 在采集页导入/采集原文，整理字段并提交审核。
2. 在审核队列通过关联机会。
3. 在 `/admin/sources` 查看完整原文，确认整篇无不宜公开的内容且具备公开使用权限，再点击“允许公开检索原文”。
4. 在学生原文检索页搜索片段。

机会卡审核通过不等于整篇附件可公开。原文默认私有；公开权限单独保存并记入审计，可随时撤销。历史版本升级时只恢复原文与已发布机会的关联，不自动开放原文。

## 检索和引用

原文按最多 900 字符切片，优先段落/句末，重叠 100 字符，保留确切字符起止位置和内容哈希。公开检索返回原文片段、版本 ID、URL、采集时间、关联机会和片段 ID。`GET /v1/knowledge/chunks/{id}` 使用同样的权限过滤，不能凭知道片段 ID 访问私有/失效内容。

只有明确公开、审核通过、机会已发布且未截止、并且仍为来源当前版本的片段可检索。新原文采集后，即使尚未审核，新版本也不会继承旧版本公开权限；旧引用停止返回，需重新核对审核和授权。

当前是确定性关键词检索：中文双字词片段/英文单词匹配，SQL 先按命中数排序再限制候选，返回最多 10 个证据片段。最多检查排序后的 300 条候选；达到上限时返回 candidate_limit_reached，提示缩小范围。无匹配返回“未找到依据”。本版不含 embedding、pgvector 或模型生成回答，不把关键词检索宣称为完整语义 RAG。

本版适合千级文档的基础检索，规模/召回需以真实语料评测；下一步可在同样的公开过滤边界内增加向量召回与重排。

## 升级

新增迁移 0011：document_chunks、knowledge_access、knowledge_publications。历史已归档发布内容的关联由审批审计记录回填；缺失审批审计或原文的旧内容不能虚构依据。首次显式允许公开时建立片段，重复操作不会增加重复片段。
