## 日历数据

`backend/app/calendar_source_manifest.json` 与
`backend/app/calendar_november_2026.json` 保存核实过的官方来源、时间节点和适用范围。
相应工具为 `scripts/import_official_calendar.py` 与 `scripts/calendar_batch.py`。

源码同步不会复制线上日历数据库。新环境需要按脚本帮助先抓取、核验，再明确执行导入；
不要把来源清单直接当成已抓取原文，不要用本地演示库覆盖线上用户数据。
已部署实例验证时，2026 年 11 月有 21 项公共日程；数量会随后续数据更新变化。

## 配置与运行

沿用 README 的依赖安装与数据库迁移流程，从 `.env.example` 配置各环境。
真实问答需要服务端模型密钥；代码中不包含密钥，也不承诺复制源码后无需配置即可调用模型。
生产环境应保持 `DEMO_MODE=false`，不得用本地预览身份模式对公网提供服务。

本地离线预览可使用 `scripts/preview_motion.py`；
真实 AI 预览使用 `scripts/start_local_ai.py`，从进程环境或当前用户安全凭据存储读取配置。
旧的静态发布脚本带特定版本保护条件，不应直接用于另一个环境或后续发布。
