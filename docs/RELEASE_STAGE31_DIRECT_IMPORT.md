# Stage31 系统导入直接展示与持久测试数据

新规则：由服务器采集 Worker 产生的内容标记为 system，完成结构化导入后自动发布，不再等待内容逐条审核；管理员可删除。手动上传仍默认 manual，保留原有审核流程，客户端不能自己指定为 system。

迁移0022增加 import_mode、test_batch、deleted_at。历史记录只有具备成功采集任务凭据才归类 system；不能凭“有URL/来自接口请求”就把手动上传误认为系统导入。后台“发布已有系统导入记录”会处理这类历史记录。已删除、已撤回或被新版本替代的内容不会被批量操作重新发布。

新数据导入后依然检查有可展示实体、原始字节hash、最新版本、来源未停用。系统直接发布不代表人工核验，不会伪造审核人。未审核政策关联不展示为已验证关系。实际外网采集的许可证、身份和网络门禁没有取消。

本工作区原有运行库没有真实已导入的系统内容，本轮不存在可“全部通过”的真实待审内容。新增并实际保留了5人、3条模拟事项、15条计划和15条订阅，模拟内容已直接发布。其标记为 demo，只能在 DEMO_MODE 下展示，不会作为真实内容在生产模式展示。

源码包包含 `demo-data/retained-demo.db`。层次和清理方法见 `demo-data/README.md`。管理员删除是可追溯软删除；彻底清理演示数据可停止服务后删除这一个专用数据库文件。

同时修复 SQLite 日期有无时区导致发布快照不一致的问题。新生成快照统一为UTC。旧已发布快照若使用不带时区日期，可能需要重新发布；未篡改原审核记录。

本轮验证：95项后端业务测试通过（明确排除2项历史迁移测试）；19项前端测试、类型检查与生产构建通过。新库升级到0022成功，独立 Alembic schema check 返回无新升级操作。SQLite完整性检查通过，实际核对5份用户资料、3条发布、15条计划、15条订阅。

完整套件在历史迁移环节异常退出，未获得完整通过结果；此前一次运行还出现后续数据库操作失败，因此不能声明97项全量测试通过。接口测试不等于浏览器交互验收，本轮没有补齐浏览器验收。
