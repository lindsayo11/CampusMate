| 探测状态 | 数量 | 实际含义 |
| --- | ---: | --- |

## 实际实现

- 按 8 类主题发现同一官方 HTTPS 主机的详情链接。跳过登录、录取名单、公示、采购、栏目首页等；不执行网页 JavaScript，不扩展到任意外链或登录系统。
- 新增 `PublicNoticeAdapter` 与通用通知入库，复用原文归档、版本、Evidence 和信息中心发布链。公开通知保持未经人工核验的事实状态；不会凭公告生成已确认的资格阈值、岗位或项目实体。
- 增加真实高校与政府页面正文容器、来源专用 selector，并修复 HTML 链接尾部空白导致的错误 404。目录、考试大纲等参考信息也能发现；未知日期保持为空。
- 原有栏目监测继续使用持久队列、条件请求、哈希去重、租约、失败退避和同主机限速。默认栏目 12 小时、正文 24 小时检查；来源可配置间隔。
- Worker 每轮最多处理 8 项公开采集任务，保留 15 秒软工作预算。单个请求仍受采集器超时约束。可用 `PUBLIC_NOTICE_WATCH_BATCH_SIZE=1..32` 调整任务数，适配扩大后的来源量。
- 来源登记不自动启用调度；运营者显式安装监测后才排队。再次安装保留暂停及操作人设置。白名单只包含已选择的可用主机；每次请求仍检查 HTTPS、TLS、公网 IP、精确主机与 robots。
- 研招网资讯、挑战杯、教育涉外监管复用既有来源编码和端点；本地先前新增的重复来源已经停用。现有许可、访问和登录 Blocker 继续生效。
- 修复来源 API 先分页后按路径筛选造成漏源的问题；筛选先执行，支持 offset 分页。
- `/data/coverage` 展示完整目录，支持名称／地区搜索、主题和探测状态筛选，同时区分抽样结果、是否安装和运行状态。既有监测异常仍可在 `/admin/notice-watch` 处理。

## 更新和运行

交接启动脚本会生成可用来源的白名单，并登记、安装栏目监测。独立操作方式：

```bash
cd backend
.venv/bin/python -m alembic upgrade head
.venv/bin/python ../scripts/refresh_postgraduate.py --install --actor local-operator
.venv/bin/python -m app.worker
```

`refresh_postgraduate.py` 保留原名以兼容旧启动流程，现在也安装其他频道。必须在环境中配置 `PUBLIC_NOTICE_WATCH_ENABLED=true` 和可用主机白名单；原来的 `COLLECTOR_ENABLED` 是另一套受校准治理的采集开关。

重新探测可运行：

```bash
backend/.venv/bin/python scripts/probe_public_sources.py --write-manifest
# 只探测选定来源；合并报告，不丢失其他来源的历史结果
backend/.venv/bin/python scripts/probe_public_sources.py --write-manifest --codes CM-HRSS-SH
```

探测器使用生产采集器的严格 robots 模式，保留 TLS 校验及公网 IP 检查；同主机串行、间隔至少 1 秒，并缓存本次已读栏目。最多 4 个栏目、一层栏目导航和 6 个不同正文样例（单栏目最多 3 个）；不产生许可证批准或校准记录。探测通过后需要重新安装，已有暂停不会被覆盖。公网部署的运行环境应重新探测和审核允许用途。本机服务退出或电脑休眠期间不会持续更新。

## 第三轮：扩展采集方式（2026-10-02）

不再仅依赖静态列表。新增统一索引发现器，所有入口继续走生产 HTTPS／TLS、公网 IP、精确主机与严格 robots 检查。列表、订阅和接口仅发现文章，不将摘要当作原文或申请资格。

| 方式 | 本轮实现 | 采集边界 |
| --- | --- | --- |
| 网页栏目与分页 | 识别 `rel=next`、Next page、下一页，以及页面明确公布的 RSS／Atom 入口 | 只跟随实际出现的官方同主机链接；辅助索引最多 16 个、深度最多 2 层，不猜页码 |
| RSS 2.0／Atom | XML 标题和文章链接发现，正常识别空订阅 | 忽略跨主机 xml:base；拒绝 DTD／实体声明，不执行脚本；全文另行抓取 |
| 匿名公开 JSON | 明确配置列表路径、标题字段和正文链接字段 | 只支持经验证的公开 GET 索引；错误结构和 JSONP 不记为健康，不发送登录信息 |
| 栏目网站地图 | 明确限定详情 URL 路径，优先最近修改文章，每轮发现最多 30 个未进入队列的 URL | 不泛爬全站。每次栏目周期读取地图并推进未发现文章；已存在正文由独立队列复查，稳定地图也不会困在首批链接 |
| 正文和附件增量 | 复用原文、PDF、哈希版本与条件请求 | 未知日期、空正文和扫描 PDF 保留问题；不把发布日或地图 lastmod 当作申请截止日期 |

待采队列达到 200 条时，暂停增加详情，保留已经发现的任务，避免一个健康栏目因容量限制被标记为解析失败。持久调度按各来源最近检查时间轮换，新增来源和已有来源都有机会执行；重启后继续使用数据库中的历史时间。暂停、访问 Blocker、租约、失败退避和同主机限速继续生效。

### 配置示例与可继续接入的方向

`public_sources.json` 的每个候选仍须通过严格探测和真实正文解析，技术通过后才由安装动作加入后台监测。

```json
{
  "discovery_format": "json",
  "json_index": {"items_path": [], "title_field": "title", "url_field": "uri"}
}
```

同一来源可以用 `index_formats` 给每个精确索引 URL 配置 `rss`、`atom`、`html` 或 `sitemap`；网站地图必须同时配置 `detail_path_prefixes`，不能使用全站根路径。含明确本地时间的来源可配置 `date_timezone` 为 IANA 时区。来源专用标题／正文 selector 与上述方式共用原文和 Evidence 入库链。

后续扩展优先处理这几类遗漏：

1. 校就业网站、竞赛平台的公开动态列表。先确认第一方接口及返回格式；中国科大本轮发现 POST 列表接口，GET 返回空数据，尚未接入。其他动态页面可在完成匿名访问、robots 和正文适配后再加入浏览器采集，不能将技术发现计为已运行。
2. 学院、实验室、国际交流和资助中心的专项栏目及官方订阅。复用本轮发现器，补充学校首页覆盖不到的导师招生、交流项目和资助变更。
3. 第一方 Word／Excel 附件与扫描 PDF。现有栏目监测只自动补抓支持的 PDF；其他附件解析和 OCR 需要保留文件及页码／位置证据，不能以下载链接代替已采集内容。
4. 对已采集的旧归档进行独立的解析升级与复核，明确区分原文发生变化和提取器改进。保持版本与公开快照一致，不为补字段伪造源内容变化。

本轮已实际实现的是表格中列出的索引方式、日期表提取和队列调度；上述后续方向尚未全部实现。
