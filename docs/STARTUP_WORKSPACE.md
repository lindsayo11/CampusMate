# 创业工作台 `/startup`

新增数据库迁移 `0028_startup_workspace.py`。参考通用的创业流程框架（顶层设计 → 主体合规 → 股权治理 → 知识产权 → 财务税务 → 融资 → 人才组织 → 市场落地 → 合规风控 → 资本化退出），把创业规划落实为独立工作台，并接入校伴 Agent。

## 功能覆盖

| 需求 | 未实现前 | 当前实现 |
|---|---|---|
| 创业信息与政策 | 已有创业发展路径、政策接入和审核框架、来源证据与版本；部分来源为 fixture 或未完成线上校准 | 保留原能力，创业信息页增加工作台入口；没有把规则草稿当作实时政策搜索 |
| 商业模式与商业架构 | 通用路径/材料建议，缺少持久化创业项目及专用设计工具 | 项目资料、九要素画布、备选收费模式、获客到交付和结算的业务链路 |
| 股权与退出 | 没有专用持股测算和进入退出文稿 | 股东贡献记录、期权池与单轮增资稀释测算、治理设计、成熟及退出条件草稿 |
| BP 与财务 | 通用材料建议，没有专用 BP 版本与财务模型 | BP 起草、单位经济/盈亏平衡/资金期限、五年及销量上下 20% 情景，测算进入 BP 和财务文稿 |
| 用户协议及隐私 | 没有创业项目专用起草与版本保存 | 用户服务协议和隐私告知草稿，按真实服务/费用/数据活动留出条件及事实缺口 |
| IPO 与资本化 | 没有专用工具 | 按项目阶段提出准备方向，比较 IPO/并购/转让等路径、资料缺口和专业核验问题，不自动认定上市资格 |
| 创业 Agent | 原有查询、资格、计划、任务、复盘及材料建议 | 新增 `startup` 咨询、`startup_document` 文稿预览；本人确认后保存为项目文稿版本 |

## 页面布局与使用顺序

入口为 `/startup`，侧栏项目列表与右侧工作区并列。手机端变为单列，标签可换行，数据表在自身容器内滚动。

| 工作区 | 内容 |
|---|---|
| 项目概况 | 名称、阶段、法域、客户市场、团队、真实运营与证据记录 |
| 商业设计 | 客户/痛点/解决方案、九要素、竞争位置；生成画布、商业架构和 MVP 验证计划 |
| 财务与股权 | 同币种假设、股东贡献、保存后测算、六项指标、稀释表、折叠情景与口径说明 |
| 文稿中心 | 主体/协议/数据资料按需展开；选择类型、生成、阅读或编辑、保存版本、下载 Markdown |
| 创业流程 | 十环节卡片、待办提示、自评勾选、相关文稿入口；勾选不代表满足法定或上市条件 |

建议先填项目名称、客户问题和真实证据，保存；完善商业设计，再填写财务及股东；最后起草对应文稿。生成草稿与保存文稿是独立操作。修改资料或同类文稿已有新版本时，服务端拒绝旧版本覆盖，请刷新后重新生成/保存。

## 十环节功能映射

| 环节 | 功能和输出 |
|---|---|
| 商业顶层设计 | 商业模式画布、商业架构、BP |
| 公司主体与工商合规 | 主体与经营合规清单 |
| 股权与公司治理 | 股权与治理设计、进入退出机制、稀释测算 |
| 知识产权与壁垒 | 知识产权与壁垒规划 |
| 财务与税务 | 财务假设、现金规划、五年情景和税务核验清单 |
| 融资全流程 | BP、融资准备与尽调清单 |
| 人才与组织 | 人才与组织设计 |
| 市场与业务落地 | MVP 与市场验证计划 |
| 合规与风险防控 | 用户服务协议、隐私告知和数据处理草稿 |
| 资本化与退出 | IPO 准备建议、并购/转让/合法回购/清算及合伙人退出选项 |

共 14 类文稿。每类支持项目输入、建议/假设、未填事实、编辑、追加版本与 Markdown 导出。未提供的市场规模、收入、客户和履历不会由规则模板编造。

常见创业科普材料中的“认缴不用实缴”“绝对避免均分”“公司默认回购”“公开后绝对不能申请”“IPO 普遍允许未盈利”等概括，没有转成固定判断。系统改为核验具体法域、主体、期限、条款及例外，并提供公司法、个人信息保护法和发行/交易所规则的官方入口。这一框架的整理日期不代表系统持续跟踪规则变化；香港、美国及其他地区不得直接套用中国大陆框架。

## 测算口径

所有金额须使用同一币种；系统不换汇。

- 单位贡献 = 单价 − 单位变动成本；月收入 = 单价 × 月销量。
- 月经营结果 = 单位贡献 × 月销量 − 月固定支出；月资金消耗 = max(−月经营结果, 0)。
- 资金期限 = 可用现金 ÷ 月资金消耗；消耗为零时不计算有限期限。
- 盈亏平衡销量 = 向上取整(月固定支出 ÷ 单位贡献)；单位贡献不为正时不计算。
- 五年情景：首年月销量 × 12；销量及固定成本分别按用户年增长假设迭代；单价和单位成本固定；另做销量上下 20% 情景。未计税费、资产投入、回款、营运资本和融资，不是审计利润或真实现金流。
- 稀释：现有持股必须合计 100%；先从现有股东同比例增设期权池，再以新增投资 ÷ (投前估值 + 新增投资) 计算投资人比例。该表只计算经济权益，不判断控制权/表决权，不覆盖可转债、SAFE、老股出售或优先权。

例：现有两位股东 70%/30%，新增期权池 10%，投前估值 100 万、增资 25 万，则测算后为 50.4%/21.6%/期权池 8%/投资人 20%。如单价 100、月销量 100、单位成本 40、固定支出 9000、现金 18000，则月收入 10000、月经营结果 −3000、资金期限 6 个月、盈亏平衡销量 150。

## Agent 与模型模式

在项目页点“与校伴讨论”，或在 `/agent` 选择创业项目和“创业文稿”。例如“请写 BP”“起草用户协议”“设计股权”。Agent 展示确定性文稿预览及项目资料版本；点击“确认保存”才新增文稿版本。重复确认复用第一次结果；跨账号、过期项目资料和文稿版本冲突会被拒绝。未选项目时先显示创业流程及项目入口。

默认模式是可运行的结构化模板加服务端测算，不依赖模型密钥。文稿中心可主动勾选模型辅助；这会把本项目资料发送至服务端配置的 Dify 服务。新增 `startup_draft` phase，输出 `markdown`。缺少配置、超时或非法输出时保留规则草稿并提示原因。Agent 的确认预览仍由平台生成，模型不能直接写数据库。真实 Dify 尚未连接验收，接入契约见 `dify/DEVELOPMENT_ASSISTANT.md`。

协议、股权和 IPO 输出都是可编辑讨论草稿；尚需按真实业务、法域及现行规则完成适用专业审查。此版没有自动办理工商、签约、税务申报、融资对接或上市申报功能。

## 数据、启动和验证

新增私有表 `startup_projects`、`startup_artifacts`。项目和文稿按账号隔离，保存使用项目 revision 与同类型文稿 version 双重冲突检查。公开演示快照已迁移到 0028，保留原有 94 条公开事项/95 个归档版本，创业项目及其他私人表为空。

首次安装及启动见根目录 [`README.md`](../README.md)。依赖安装和生产构建完成后，在根目录运行：

```bash
backend/.venv/bin/python scripts/start_local.py --collector-off
```

打开 `http://127.0.0.1:3000/startup`。启动器先升级数据库；默认演示不需要真实账号或模型。使用自己的数据库时先备份，再执行迁移，不要把生产数据库混进演示快照。

验证：后端全量 189 项测试通过；最后文稿调整另复验创业 16 项。前端 19 项测试、TypeScript 和 Next.js 生产构建通过。桌面与 Pixel 7 共 6 项浏览器测试通过，含创业完整操作和既有 Agent 回归；页面中文字体已扩展，桌面/手机未发现横向页面溢出。

复验时先在全新演示数据库迁移到 head，并设置 `DATABASE_URL`、`DEMO_MODE=true`、`ENABLE_AGENT_UI=true` 后在 backend 目录运行 `python -m pytest tests -q`。浏览器验收入口：

```bash
backend/.venv/bin/python scripts/verify_agent_ui.py
```

需要先完成 frontend 生产构建并安装 Playwright Chromium；可用 `CHROMIUM_PATH` 指定已有浏览器。验收启动隔离 API/Web 和临时数据库，使用 8035/3035 端口。

尚未验收：真实 Dify、Supabase 登录/邮件、生产 PostgreSQL、原生 Windows、Docker/TLS 公网部署。迁移与并发保存目前在 SQLite 验证；版本保护不能代替 PostgreSQL 上的实际验收。本仓库提供本地演示与继续开发用途，不含任何已公开部署的实例。
